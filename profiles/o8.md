# o8 compiler profile

o8 is a control room (`harnesses/catalog.json` `kind: control-room`). Compilers live in the harness repo. AODL does not become o8's scheduler.

Export (o8 side): `o8 mission export --format observed-graph` — [hurttlocker/o8#2230](https://github.com/hurttlocker/o8/issues/2230). Acceptance on this side is `python3 tests/validate.py` against the emitted document.

## Mapping

| o8 | AODL |
|---|---|
| Product (control room) | catalog `kind: control-room` — never a node |
| Orchestrator CLI | `executor` + `harness` if the id is in `supported` |
| Packet | `task` (intent). Retry is not a second task. |
| Lane | observed execution (`eventLog` + `observedGraph`) |
| Review | `verifier` |
| Approval / merge | `humanGate` |
| Signed receipt | sealed `evidence` |
| Cortex | `memory` / `stateStore` |
| Mission as a list | many components, no invented `dependency` |

`o8` never appears as `executor.harness`. There is no `control-room` or `observer` node kind.

## Events

o8 lane events today are id, verb, actor, payload, timestamp. HOTL events require `causalParents`, `revision`, and `sourceHash`.

- Linear lane-log → `causalParents: [prev]` (first event of a lane: `[]`)
- Per-lane `revision` counter
- `sourceHash` of the packet brief
- Non-mutation verbs → `stateUpdate` payload
- Unmapped o8 CLIs omit `harness`. Do not bulk-add runtimes to `supported`.

## `humanGate` ≠ review

The gate is the irreversible action (merge, deploy, approve). Review may be delegated to an orchestrator as a `verifier`. That is a `verification` / `critique` edge, not a transfer of gate identity.

Fixture: `examples/valid/o8-mission-list.json` (two packets, shared verifier + humanGate, no `dependency` between packets, optional `observedGraph` + `eventLog`).
